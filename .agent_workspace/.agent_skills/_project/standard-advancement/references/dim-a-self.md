# 视角 A：标准自身质量

评估这篇标准本身编制得如何、是否及时更新、结构完整性等内在特征。

## 数据采集

| 数据项 | 工具 | 参数 |
|---|---|---|
| 元数据 | `standard_query` | 查 `standard_base_info` 取完整行（加 `deleted = 0`） |
| 正文目录 | `get_standard_chapters` | `toc_only=true` |

---

## 检查要点与关注点触发条件

### 1. 时效性

数据来源：`issue_date`、`act_date`、`annul_date`、`state`、`target_stds`

| 触发条件 | 关注点 |
|---|---|
| 发布距今 >10 年 且 状态仍为"现行" | 标准发布久远且长期未更新，时效性存疑 |
| `target_stds` 有值（已被新标准替代） | 本标准已被替代，应确认是否仍在使用 |

### 2. 技术结构完整性

数据来源：`get_standard_chapters(toc_only=true)`

| 触发条件 | 关注点 |
|---|---|
| 无"技术要求"或"性能要求"章节 | 缺少核心技术规定 |
| 无独立试验/检测方法章节（仅引用其他标准） | 检测方法依赖外部标准，独立性弱 |
| 无任何附录（规范性或资料性） | 技术支撑材料缺失 |

### 3. 标准层级与性质

数据来源：`std_type`、`std_nature`

| 触发条件 | 关注点 |
|---|---|
| 团体标准或地方标准（非国标/行标） | 层级较低，适用范围受限 |
| 推荐性标准但在强制性领域使用 | 法律效力存在缺口 |

### 4. 起草单位

数据来源：`draft_unit`（或 `draft_unit_main`）、`lead_unit`

| 触发条件 | 关注点 |
|---|---|
| `draft_unit` 为空或不明确 | 起草单位不可查，技术来源不透明 |

```
**时效性**

- 废止：[未废止 / 已废止 YYYY-MM-DD]
- [关注点 或 无问题]

**技术结构**
- 关键章节：[列出]
- [关注点 或 无问题]

**标准层级**
- {国标/行标/团标}，{强制性/推荐性}
- [关注点 或 无问题]

**起草单位**
- {列出前 3 家}
- [关注点 或 无问题]
```

---

## 注意事项

- 若 `issue_date` 为空，注明"发布日期不详"
- 若无法读取正文，技术结构部分注明"正文不可查，仅按元数据评估"
