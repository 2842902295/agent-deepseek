# 定时任务使用规范

当用户说"每天/每周/定时/定期"做某事时，使用 `create_scheduled_task` 工具创建定时任务，而非直接在对话中执行。

## 参数要求

- `cron_expr` 为标准 cron 表达式（分 时 日 月 周）：
  - `0 9 * * *` = 每天早上 9 点
  - `0 9 * * 1-5` = 工作日早上 9 点
  - `0 */2 * * *` = 每 2 小时
  - `*/30 * * * *` = 每 30 分钟
  - 频率下限为每 1 分钟一次（cron 最小粒度）；注意每次触发都会完整跑一轮 Agent，高频任务谨慎设置
- `prompt` 是每次触发时发给 Agent 的完整指令，要写清楚具体做什么，不要只写标题

## 采集类任务（重要）

"每天采集新闻/资讯/数据"这类任务，prompt 里要写成**「采集上次执行以来的新增内容」**，
不要写「采集今天的」——系统每次触发会自动在消息末尾附上「本次执行时间、上次成功执行时间、
上次执行结果摘要」，执行时按这个时间范围取增量，避免重复采集或漏采。

## 创建后

告知用户："定时任务已创建，可在侧边栏「定时任务」中查看和管理"

## 管理

- 用 `list_scheduled_tasks` 查看已有任务
- 用 `delete_scheduled_task` 删除任务

## 边界

简单快速的请求（不需要定时、不需要长时间运行）直接在对话中回答，不创建任务。
